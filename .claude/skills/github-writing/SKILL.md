# github-writing — 読み手が一読で行動できる文章を書く

GitHub 向けの文章 (PR 本文 / Issue・PR スレッドのコメント / レビューコメント) が対象。
「言いたいことは全部書いてあるが、何をすればいいか分からない」文章を防ぐ。網羅性より
可読性と行動可能性を優先する。ドキュメント全般の絵文字禁止は CLAUDE.md の
Documentation Style 節を継続して守る。

## 4つの役割を混ぜない

事実・判断・依頼・次アクションを段落または見出しで分離する。1つの長い段落に事実と
理由と経緯を詰め込まない。

1. **事実**: 観測・計測・コードから確認できたこと
2. **判断と理由**: 何をどう決めたか、なぜか
3. **依頼**: 相手にしてほしいこと (確認・承認・修正など)。埋もれさせず、探さなくても
   見つかる位置に置く
4. **次アクション**: これを読んだ人が次に何をすればいいか

依頼が無い文章 (質問への回答など) では 3 を省いてよい。ただし省いたことを意識的に
判断すること。

分離の手段 (見出し / 太字ラベル / 段落分け) は文章量に応じて選んでよく、4つ全てに
機械的に見出しを立てる必要はない。内容が薄い役割は隣接する役割の段落に含めてよい。
ただし性質の違う内容 (例: 事実と判断) を同じ文の中で混在させないこと。

## 用語と網羅性

- 専門用語・内部の task_id・内部でしか通じない略語は、初出で開くか、開けないなら削る。
  相手が知らない語で説明しない
- 「やったこと全部」を書かない。相手の判断や行動に必要な情報だけを本文に置き、根拠・
  ログ・検討経緯は `<details>` に畳むか報告ファイルへのポインタにする
- 冒頭で結論を書く。経緯から書き始めない。読み手は最初の数行で「何の話で、自分は何を
  すればいいか」を掴めること
- 1文だけの段落を空行で細かく区切って縦に間延びさせない。関連する項目は箇条書きに
  まとめ、連続する空行 (2行以上) は作らない
- 他リポジトリの Issue / PR を参照するときは `owner/repo#番号` で書く。`#番号` だけだと
  投稿先リポジトリの同番号を指し、別物に誤リンクするかリンクにならない

## 投稿前の自己チェック

一読しただけで次の3つをそれぞれ1文で言えるか確認する。言えないなら投稿しない。

- (a) 今どうなっているのか
- (b) 我々が何をどう決めたのか、なぜか
- (c) 自分 (読み手) が何をすればいいのか

## 対象ごとの違い

以下は「4つの役割を混ぜない」を土台にした、対象別の追加要件。基礎原則を置き換える
ものではなく、レビューコメントのように役割を簡略化する場合も「事実と依頼・判断を
混ぜない」という原則自体は保つ。

- **PR 本文**: 読み手はレビュアー。冒頭で「何をレビューしてほしいか」と影響範囲を示す。
  実装過程のログや試行錯誤は `<details>` に畳む
- **Issue・PR スレッドコメント**: 会話の一部であることを意識する。直前の質問に対する
  回答という体裁を保ち、前提の再掲は最小限にする
- **レビューコメント**: 指摘ごとに blocking (このままではマージ不可) か non-blocking
  (nit・提案) かを明示する。これが無いと著者はどこまで直せばよいか判断できない。
  個別の指摘は必ず該当行の行コメント (inline review comment) として付ける。本文に
  `file:line` + コードブロック引用でまとめる書き方は使わない。行コメントなら著者が
  該当箇所を探さずに diff 上で直接解決できる。レビュー本文には全体の判断・検証結果・
  依頼だけを残す。対象コードを示さない「〜が問題です」「〜を修正してください」だけの
  指摘は書かない

## レビューコメントの投稿手順

`gh pr review --comment --body-file` は本文しか送れず、行コメントは付かない。行コメントは
API を直接叩く。

```
gh api -X POST repos/OWNER/REPO/pulls/N/reviews --input - <<'EOF'
{"commit_id": "<head SHA>", "event": "COMMENT", "body": "<全体の判断・依頼>",
 "comments": [
   {"path": "path/to/file", "line": 23, "side": "RIGHT", "body": "non-blocking / nit\n\n..."},
   {"path": "path/to/file", "start_line": 15, "line": 21, "side": "RIGHT",
    "start_side": "RIGHT", "body": "non-blocking / 提案\n\n..."}
 ]}
EOF
```

- 複数行にまたがる指摘は `start_line` + `start_side` を足す
- 行番号は変更後ファイルの行番号。diff に現れない行にはアンカーできない
- 提出済みレビューは削除できない (`Can not delete a non-pending pull request review`,
  HTTP 422)。本文を差し替えるときは `PUT repos/OWNER/REPO/pulls/N/reviews/{review_id}`
  で body を更新する。書き換え前に現在の body を必ず fetch する
