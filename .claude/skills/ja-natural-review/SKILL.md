# ja-natural-review — 仕事の日本語文書を自然に整える

書き終えた日本語の文章を、機械での検出と読み直しの2段で整える。目的は読み手が引っかからずに
読めること。言っている中身は変えない。文章の出自（AIか人か）を判定するためのものではない。

先行する取り組みを土台にしている。

- [textlint-ja/textlint-rule-preset-ai-writing](https://github.com/textlint-ja/textlint-rule-preset-ai-writing)（MIT, azu）：
  AI が書いた文章に多い形（太字ラベルの箇条書き、述語のあとのコロン、誇張表現、太字の多用）を機械的に検出する。
  `scripts/check.py` は、このルールのうち正規表現で拾える分を移したもの
- [geonwoo-jeong/japanese-humanizer](https://github.com/geonwoo-jeong/japanese-humanizer)（MIT）：
  翻訳調・冗長表現・係り受けなどの分類と優先度（P1〜P3）。下の「読み直しの目印」はその quick-rules を
  仕事の文書向けに絞ったもの。小説・翻訳・高リスク文書（法務・医療・契約）を直すときは、こちらを使う

## 手順

1. 誰が何のために読む文章かをつかむ（会議資料、Slack、手順書、報告書など）
2. **機械で検出する**

   ```bash
   python3 <squad のルート>/.claude/skills/ja-natural-review/scripts/check.py <ファイル.md>
   ```

   標準ライブラリだけで動く。textlint の ai-writing のルールのうち正規表現で拾える分（太字ラベルの
   箇条書き、箇条書きの先頭の絵文字、見出し・文中の太字、述語のあとのコロン、大げさな言葉）と、
   japanese-humanizer の P1 のうち機械で拾える分（冗長な言い回し、100字を超える文）、型どおりの締め、
   文中の矢印を見る。`npx` で textlint を取ってくる方法は、依存パッケージの乗っ取りが怖いので使わない。
   検出は「見直す候補」であって、全部直す義務ではない。表の中の ✅／❌ のように、意味を持たせて
   使っているものは残してよい
3. **読み直す**：下の「読み直しの目印」に当たる箇所を探す。P1 から順に直す
4. 直す。直すときの決まり
   - 事実・数値・日付・固有名詞・コマンド・パス・URL・結論・条件・否定を変えない。足さない、削らない
   - 敬体／常体、硬さ、読み手との距離は元のまま
   - 表・コードブロックは崩さない。構成（見出しの順番）は、読みにくさの主因でない限り変えない
   - 局所的に直す。全体を書き直したくなったら、元の構成で済まないかを先に考える
5. 直したあとに通して読み、元の文章と中身が同じかを確かめる。2 の検出をもう一度流して、残りが
   意図して残したものだけかを見る
6. 報告は短く。目立つ直しを3〜5例だけ「前 → 後」で示す

頼まれたのがレビューだけなら、4 を飛ばして「場所・前・後・理由」の一覧を返す。

## 読み直しの目印

ID は japanese-humanizer の分類。P1 ほど先に直す。

### 形（textlint でも多くは拾える）

| 目印 | 優先度 | 直し方 |
| --- | --- | --- |
| `- **ラベル**：説明` の箇条が延々と続く（JA-AI-13） | P2 | 手順や比較なら表にする。説明なら普通の文にする。本当に見出しの役なら見出しにする |
| 文中の太字、見出しの中の太字 | P2 | 太字は1画面に数か所まで。強調しなくても読める文にする |
| 述語のあとのコロン（「次のとおりです：」「実行します:」）でリストや表につなぐ | P2 | 「次のとおりです。」と句点で終える |
| 1文で言えることを箇条に細切れにしている／並列でないものを箇条にしている | P2 | 文に戻す |
| `→` で文をつなぐ | P2 | 流れ図・手順の中だけにする。文では「〜して、〜する」 |
| 数行しかない節に見出し | P3 | 見出しを外して前後の段落に入れる |

### 言い回し

| 目印 | 優先度 | 直し方 |
| --- | --- | --- |
| 「〜することができる」「〜することが可能」（JA-TL-05） | P1 | 「〜できる」、または現在形 |
| 「検討を行う」「実施を行う」（JA-TL-04） | P1 | 「検討する」「実施する」 |
| 「〜について」「〜に関して」「〜における」の連発（JA-RB-19） | P1 | 「〜を」「〜で」「〜では」「〜の」 |
| 「〜することとする」「〜ということになる」、二重否定（JA-RB-19） | P1 | 「〜する」。慎重さが要る文脈なら残す |
| 「〜を可能にする」「〜を実現する」「〜を提供する」「〜を活用する」（JA-TL-02） | P3 | 「〜できる」「〜を作る」「〜を出す」「〜を使う」 |
| 「重要」「鍵となる」「包括的」「不可欠」「大幅に」が根拠なく多い（JA-AI-12） | P3 | 強調語を削り、対象・条件・理由を前に出す。根拠や数字は作らない |
| 読み手に定着していないカタカナ語（JA-TL-06） | P3 | 日本語で言えるなら日本語に。現場で普通に使う技術用語はそのまま |
| 「〜させていただきます」「〜いただけますと幸いです」の連発 | P2 | 1か所に絞るか、「〜します」「〜してください」 |

### 流れ・締め

| 目印 | 優先度 | 直し方 |
| --- | --- | --- |
| 文の長さが均一、または100字を超える文が続く（JA-WR-09） | P1 | 意味の切れ目で分ける |
| 主語と述語が遠い、1文に論点が複数（JA-WR-09） | P1 | 主述を近づける。1文1論点を目安に分ける |
| 「の」の連続、同じ助詞の近接（JA-WR-08） | P1 | 語順を変えるか、動詞にしてほどく |
| です・ます／だ・である、全角／半角の混在（JA-WR-21, JA-SP-23） | P1 | 文書内でそろえる。表・UIラベル・引用は除く |
| 「まず」「さらに」「一方で」「最後に」の型どおりの並び（JA-AI-11） | P2 | 1〜2個だけ残し、ほかは文の流れに溶かす |
| 「このように」「まとめると」「〜が期待されます」で締める（JA-AI-14） | P2 | 締めの段落を削るか、本文にある判断・条件・次の行動だけで終える |
| 冒頭の要約・本文・最後のまとめで同じことを3回言う | P2 | 要約か本文のどちらかに寄せる |
| 自分の作業を実況する（「まず〜を確認しました。次に〜しました」） | P2 | 読み手に要る結果だけ書く |
| 「と考えられます」「可能性があります」が続く（JA-MT-22） | P2 | 分かっていることは言い切る。分からないことは「未確認」と一度だけ書く。確信度そのものは変えない |

## 直し方の例

| 前 | 後 |
| --- | --- |
| 本Skillを活用することで、PDFからのテキスト抽出を可能にします。 | この Skill を使うと、PDF の本文を取り出せます。 |
| - **結論**：直接読ませる方式を推奨します。<br>- **理由**：高速かつ低コストであるため。 | 直接読ませるのがよいと思います。速くて安いからです。 |
| 問いかけリスト生成 → 品質チェック → 承認という流れになります。 | 問いかけリストを作り、品質チェックをして、承認を受けます。 |
| 品質の大幅な向上を実現しました。 | 品質がよくなりました。（具体的な数字が原文にあれば、それを前に出す） |

## やらないこと

- 敬語の度合い・文体を元の文章から変える
- 専門用語を一般語に置き換えて意味をずらす
- 受け身・カタカナ語・抽象語を機械的に全部消す
- 原文にない例・数字・根拠を足す
- 検出ツールの指摘を全部つぶすことを目的にする
